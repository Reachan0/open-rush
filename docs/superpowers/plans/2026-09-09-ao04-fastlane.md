# AO-04 Fastlane Implementation Plan

> **Execution note:** Earlier implementation used isolated workers. Final review and fixes are performed directly in the two dedicated worktrees. No commit or push in this iteration.

**Goal:** Execute AO-04's protected local dependency through the existing DSH fastlane, retain completed work on failure, and demonstrate recovery without replaying the graph.

**Architecture:** Both direct DSH calls and graph nodes invoke the same registered `ao04_read_status` tool and Python controller. The workflow engine stays independent of AO-04: runtime configuration controls tool eligibility and a result adapter converts protected failures into explicit node failures. Calls sharing a managed dependency serialize within that instance so they share its repair budget; different instances remain independent.

**Tech Stack:** TypeScript, Cordis/DSH, existing workflow engine, Vitest, Python/Flask, unittest.
